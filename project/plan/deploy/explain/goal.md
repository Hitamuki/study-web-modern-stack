# いま何が問題か

このアプリは **`make dev` で自分のパソコンを動かしているときにしか存在しません。**

```text
自分の PC                    インターネット
┌──────────────┐
│ Docker        │
│  PostgreSQL   │                （なにもない）
│  Hasura       │
│ NestJS / Vite │
└──────────────┘
```

つまり次ができません。

| できないこと | なぜ困るか |
| :- | :- |
| 他の人に見せる | URL を渡せない |
| スマホから触る | `localhost` は自分の PC の中だけを指す言葉 |
| 動き続けさせる | PC の電源を切ると止まる |

README の【成功の定義】5「**AWS でサービスが稼働すること**」が未達なのがこの状態です。
この条件自体を「**無料枠のサービスで常設稼働すること**」へ書き換えます（層 2 / #99）。

# 目的

**インターネット上に置きっぱなしにする。しかもお金をかけずに。**

そして **その構成を手作業ではなく設定ファイル（Terraform）で管理する。**

# ゴール（これができたら完了）

| # | できること |
| :- | :- |
| 1 | 公開 URL を開くと、ログイン画面が出る |
| 2 | アカウントを作り、ログインして、自分のメモを作成・編集・削除できる |
| 3 | **他人のデータに触れる裏口が無い** |
| 4 | **月額の請求が発生しない** |
| 5 | 環境の構成が `infra/` の Terraform に書かれている（**段階 3 で作り直す**） |
| 6 | `main` にマージすると、公開環境へ自動で反映される |

# なぜやるのか

理由は 3 つあります。

## 1. 作ったものは動いて初めて完成だから

ローカルで動くことと、インターネットで動き続けることの間には**大きな差**があります。
`localhost` という言葉が使えなくなり、秘密の値を安全に渡す方法が要り、
落ちたときに誰も再起動してくれません。**この差を体験するのが学習の中身**です。

## 2. お金をかけずに続けたいから

学習用のアプリに月額を払い続けるのは現実的ではありません。
既存の `infra/` は AWS の **RDS**（データベースのサービス）を定義していましたが、
これは**起動しているだけで課金されます**。**使う予定が無くなったので削除します**（層 2 / #99）。

だから「無料の範囲でどこまでできるか」を探すのがこの計画です。
**無料には無料の理由があり、その代償を理解すること自体が学習になります。**
→ [free-tier.md](/project/plan/deploy/explain/free-tier.md)

## 3. 手作業で作った環境は再現できないから

ブラウザの管理画面をポチポチして作った環境は、**何をどう設定したか誰も覚えていません。**
壊れたときに元に戻せず、同じものをもう 1 つ作れません。

Terraform は**その手順をコードとして書き残す**道具です。
→ [iac.md](/project/plan/deploy/explain/iac.md)

# やらないこと

| やらないこと | 理由 |
| :- | :- |
| モバイル版・デスクトップ版の公開 | 開発を止めているため |
| 独自ドメインの取得 | サービス名が未決（Discussion #46）。**借りたサブドメインで公開できる**ので待ちません |
| 監視・アラートの整備 | まず動かすことを優先します |
| 自動テストの追加 | 現在テストは**1 件もありません**。別の課題として切り出します |

# 順番が決まっている

**「どこに置くか」より先に「置ける状態にする」必要があります。**

いまのコードには、公開すると危険な箇所と、そもそもクラウドでは動かない設定が残っています。
置き場所が決まるのを待たなくても直せるので、**先に直します。**

詳しくは [../objective.md](/project/plan/deploy/objective.md) の「2 つの段階に分かれる」を参照してください。
