# なぜ無料で提供できるのか

**慈善事業ではありません。** 理由は 3 つあります。

| 理由 | 提供側の狙い |
| :- | :- |
| **お試し** | 気に入ったら有料プランへ移ってほしい |
| **余りもの** | どうせ空いている計算資源を配っている |
| **囲い込み** | 移りにくくして、大きくなったときに課金したい |

どの理由でも、**「使われていないものにコストをかけたくない」**のは共通です。
そこから代償が生まれます。

# 代償 1: 休止（スリープ）

**一定期間アクセスが無いと止まります。**

止まり方には 2 種類あり、**危険度がまったく違います。**

| 種類 | 何が起きるか | 危険度 |
| :- | :- | :- |
| **スリープ** | 次のアクセスで起きる。ただし最初の 1 回が遅い（コールドスタート） | 低い |
| **一時停止・削除** | 手動で戻すまで止まったまま。**放置するとデータごと消える** | **高い** |

Discussion #29 の評価軸 2 が
「**DB のデータが消える条件は致命的**」と書いているのはこのためです。

## このプロジェクトに直撃する問題

Supabase の無料プランは **7 日間アクセスが無いとプロジェクトが一時停止し、
90 日を過ぎると復元できません**（確認日 2026-08-17、Discussion #29 のコメント）。

**学習プロジェクトには利用者がいません。** 自分が 1 週間触らなければ止まります。

対処は 3 つありますが、**どれも一長一短です。**

| 案 | 問題点 |
| :- | :- |
| 止まったら手で戻す | 「常設する」という目的を満たさない |
| 定期的に自動アクセスする | **サービスの想定利用から外れた使い方**。規約の観点で判断が要る |
| 別のサービスを使う | 認証と DB が別々になり、管理が煩雑になる |

**この判断は Discussion #29 で決めます。** → [../decision.md](/project/plan/deploy/decision.md)

# 代償 2: 制限

無料枠には必ず上限があります。よくあるのは次の 5 つです。

| 制限 | 意味 |
| :- | :- |
| **メモリ / CPU** | 小さいと重いプログラムが動かない。**Hasura はここが効く** |
| **転送量** | 月に配れるデータ量の上限 |
| **ビルド時間** | CI が動ける時間の上限 |
| **プロジェクト数** | 作れる環境の数。**Supabase は 2 つまで** |
| **同時接続数** | DB に同時につなげる数 |

**「同時接続数」は見落としやすい制限です。** Hasura はデータベースへの接続を
何本か張りっぱなしにするため、上限の小さい無料 DB とは相性に注意が要ります。
→ [../findings.md](/project/plan/deploy/findings.md) の 6

## 商用利用の禁止

**制限は技術的なものだけではありません。** 規約で商用利用を禁じている無料プランがあります。

学習用なら問題になりませんが、**将来収益化する可能性がある**なら
（Wiki [Monetization](https://github.com/Hitamuki/study-web-modern-stack/wiki/Monetization)）、
選ぶ時点で確認しておく必要があります。

# 代償 3: 撤退

**無料枠は予告して消えます。** これが一番の落とし穴です。

近年、複数のサービスが無料枠を縮小・廃止しました。
**「去年の記事に書いてあった無料枠が、今はもう無い」ことが普通に起きます。**

だから Discussion #29 の本文は候補表の数値を**あえて空欄**にしており、
「無料枠の条件は変動が激しいため、**検証時に各公式から確認日付つきで埋める**」としています。

> [!IMPORTANT]
> **この解説にも具体的な数値をほとんど書いていません。意図的です。**
> 数値の正本は Discussion #29 です。ここに写すと、古い値が残って読む人を誤らせます。

同じ理由で、**選定は「いま無料か」だけで決めません。**
評価軸 6「移行コスト」が入っているのはこのためです。
**撤退されたときにどれだけ楽に逃げられるか**を先に見ておきます。

認証で Supabase を選んだときも、決め手は
「パスワードのハッシュを `pg_dump` で持ち出せる = **乗り換えコストが候補中で最も低い**」でした
（Discussion #19）。**同じ考え方をホスティングにも使います。**

# まとめ

**無料枠を使うとは、お金の代わりに別のものを払うことです。**

| 払うもの | 具体的に |
| :- | :- |
| **速度** | コールドスタートで最初のアクセスが遅い |
| **安定** | 止まる。消えることもある |
| **手間** | 複数のサービスにまたがり、管理が煩雑になる |
| **将来** | 撤退されたら引っ越す |

**この計画では「速度」と「安定」を差し出します。** 学習用のアプリなので、
最初のアクセスが数秒遅くても、月に一度止まっても、致命的ではないからです。

**差し出さないものが 1 つだけあります。データが消えることです。**
だから Supabase の 90 日ルールだけは、[decision.md](/project/plan/deploy/decision.md) で
必ず結論を出してから進めます。
