# いま何が問題か

このアプリのフロントエンドは、Hasura（データベースの入口）に **admin secret** という
**全権限を持つ合言葉**を使って接続しています。

しかもその合言葉は**プログラムに直接書かれていて、ブラウザの開発者ツールから見えます。**

```
packages/graphql/src/ApolloProvider.tsx
  adminSecret = "myadminsecretkey"   ← 誰でも読める
```

つまり公開すると、**誰でも全ユーザーのメモを読み書き・削除できます。**

## なぜこうなっていたか

手抜きではなく**必然**でした。データベースに「誰が何を見てよいか」の設定が
1 つも書かれていないため、**全権限の admin でしか接続できなかった**のです。

# 目的

**admin secret を消し、「ログインした人が自分のメモだけを操作できる」状態にする。**

# ゴール（これができたら完了）

| # | できること |
| :- | :- |
| 1 | メールアドレスとパスワードでアカウントを作れる |
| 2 | ログインすると**自分のメモだけ**が表示される |
| 3 | **他人のメモは見えない・編集できない・削除できない** |
| 4 | ログインしていないと何も取得できない |
| 5 | パスワードを忘れても再設定できる |
| 6 | プログラムのどこにも admin secret が無い |

# なぜやるのか

**公開できないから**です。このままでは学習用にインターネットへ出した瞬間に、
誰でもデータを消せる状態になります。

もう 1 つは**学習として避けて通れない**からです。認証・認可はどんなサービスにも必要で、
「トークンを発行して、検証して、権限で絞る」という流れはどの技術を使っても共通します。

# やらないこと

- モバイル版・デスクトップ版への導入（開発を止めているため）
- ソーシャルログイン（Google など）。メール + パスワードが動いてから検討する
